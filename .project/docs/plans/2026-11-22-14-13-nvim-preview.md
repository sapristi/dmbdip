# Neovim Preview Plan

**Spec:** `.project/docs/specs/2026-11-22-14-13-nvim-preview-design.md`
**Goal:** `dmbdip --serve` headless JSON render server plus a minimal Lua plugin (`:DmbdipPreview`) that shows a live, scroll-synced preview in a neovim split via kitty unicode placeholders.
**Approach:** Add a serve module to the binary crate that renders buffer text, cuts the page into ≤297-row strips, writes changed strips as raw RGB files that kitty reads and deletes (`t=t`), and replies with strip descriptions and a source-line → row map. The repo root becomes a neovim plugin that drives the server and paints placeholder cells.

## Constraints

- The spec is authoritative for protocol field names and shapes (request: `id,type="render",text,cols,cell_w,cell_h`; response: `id,type="render",cols,total_rows,strips[{index,rows,path|null}],anchors[[line,row]]`; error: `id|null,type="error",message`).
- Max 297 rows per strip. Render width = `cols × cell_w`; image height padded up to a multiple of `cell_h` with `theme.bg`.
- Strip file name: `dmbdip-<pid>-tty-graphics-protocol-<n>.rgb` (must contain `tty-graphics-protocol`), raw RGB row-major, no header, in `/dev/shm` if it exists else `std::env::temp_dir()`.
- Serve mode writes nothing to stdout but JSON response lines; diagnostics to stderr / `--debug` log.
- TUI behaviour must not change (fold arrows still drawn in the TUI).
- Every kitty graphics command from Lua goes through `Snacks.image.terminal.request()` (adds `q=2`, tmux passthrough).
- Image ids: random base in `[0x100000, 0xFF0000)` per preview, strip `i` → `base + i`.
- Commit messages: conventional style as in `git log`, no "Co-authored-by".
- Pre-existing untracked/uncommitted files: none at plan time; leave anything that appears alone.

## Risks

- Strips scaled by kitty (blurry/wrong aspect) if strip px size ≠ `cols×cell_w` by `rows×cell_h` → test asserts exact dimensions; manual check text is crisp.
- Kitty replies leaking into neovim input (garbage typed into buffer) → all commands via `Snacks.image.terminal.request` (q=2); manual check.
- Leftover strip files in `/dev/shm` after closing (kitty deletes on read, but files written for a response never applied, or server exit) → server removes files it wrote that still exist on EOF; manual check `ls /dev/shm/dmbdip-*` empty after close.
- Malformed request or render panic killing the server → error response and loop continues; unit test.
- Unchanged text re-sending all strips (slow typing) → test: second identical render returns all `path: null`.

### Task 2: Serve module and `--serve` flag

**Touches:** `Cargo.toml` (add `serde_json = "1"`), new `src/serve.rs`, `src/main.rs`

1. In `src/serve.rs`, define serde types for request/response/error per the spec (request deserialized with `#[serde(tag = "type")]` or equivalent; unknown `type` → error response).
2. `pub(crate) fn run_serve(input: impl BufRead, output: impl Write, fonts: &Fonts, theme: &Theme, layout: &LayoutParams, out_dir: &Path) -> io::Result<()>`: loop over lines; skip empty lines; for each, handle the request inside `std::panic::catch_unwind(AssertUnwindSafe(..))`; write one JSON line and flush after each request. On EOF, remove any strip files it wrote that still exist, then return.
3. Server state kept across requests: `MermaidCache`, last `(cols, cell_w, cell_h)`, per-strip `(rows, hash)` of the last response, counter `n` for file names.
4. Render handling: `parse_markdown(text)` → `(blocks, block_source_lines)`; `build_headings`; `render_markdown(..., width = cols*cell_w, vp_height = 0, ..., fold_arrows = false)`; pad height to a multiple of `cell_h` (min one row); split into strips of up to 297 rows; hash each strip's bytes (`DefaultHasher`); a strip is changed if its index is new, its rows or hash differ, or `(cols, cell_w, cell_h)` changed. Write changed strips to `out_dir` and give their path; others `null`.
5. Anchors: for each `(block_index, y)` in `block_positions`, emit `[block_source_lines[block_index], y / cell_h]`, sorted by line.
6. Validate `cols ≥ 1`, `cell_w ≥ 1`, `cell_h ≥ 1` and that `cols*cell_w` is wider than `layout.margin_left + layout.margin_right` (else error response, no panic).
7. `fn strip_dir() -> PathBuf`: `/dev/shm` if it is a directory, else `std::env::temp_dir()`.
8. In `src/main.rs`: add `mod serve;`, a `serve: bool` arg for `--serve`, a line in `print_help`. When set: after `debug::init`, skip graphics detection and viewport size query, load config/theme/layout/fonts, call `run_serve(stdin.lock(), stdout.lock(), …, &strip_dir())`, exit with its result.
9. Tests in `src/serve.rs` (use `test_helpers` fonts/theme and a `tempdir` under `std::env::temp_dir()` created per test): 
   - first render: strip rows sum to `total_rows`, all paths set, each file size = `cols*cell_w * rows*cell_h * 3`, every strip ≤ 297 rows (use a long enough document to get ≥2 strips);
   - identical second render: all paths `null`;
   - edit near the end of a multi-strip document: first strip `null`, last strip has a path;
   - changing `cols` → all strips have paths;
   - anchors: sorted by line, rows non-decreasing, first anchor row matches `paragraph_gap / cell_h`;
   - malformed line (`not json`) → `{"type":"error","id":null,...}` and a following valid request still gets a render response;
   - EOF cleanup: files not deleted by the test are removed after `run_serve` returns.

**Check:** `cargo test` passes; `printf '{"id":1,"type":"render","text":"# Hi\\n\\nworld","cols":60,"cell_w":10,"cell_h":20}\n' | cargo run -q -- --serve` prints one JSON line with one strip whose path exists in `/dev/shm` (then delete it by hand). Commit `feat(serve): headless --serve render mode for editor previews`.

### Task 3: Neovim plugin

**Touches:** new `plugin/dmbdip.lua`, `tests/nvim/smoke.lua`, `lua/dmbdip/init.lua`, `lua/dmbdip/diacritics.lua` (and further modules under `lua/dmbdip/` at the implementer's discretion), `Cargo.toml` `exclude` (add `"lua/"`, `"plugin/"`)

1. `lua/dmbdip/diacritics.lua`: the 297 row/column diacritic codepoints from kitty's `rowcolumn-diacritics.txt` (fetch the raw file from `https://raw.githubusercontent.com/kovidgoyal/kitty/master/gen/rowcolumn-diacritics.txt`), as a Lua array of UTF-8 strings, index 1 = row/col 0.
2. `require("dmbdip").setup({ cmd = "dmbdip", debounce_ms = 150 })`, options optional; module works with defaults without calling setup.
3. `plugin/dmbdip.lua`: user command `:DmbdipPreview` toggling the preview for the current buffer.
4. Implement open / render requests / applying responses / scroll sync / close exactly as in the spec's "Neovim side" section, including: one job per source buffer (state keyed by bufnr), at-most-one request in flight with a pending flag, re-render on cols change (`WinResized`/`VimResized`), buffer lines rewritten only when geometry changes, per-id highlight groups `DmbdipImg<id>`, image deletion for dropped strip indices and on close, the scroll-driving window rule (most recently entered window showing the source buffer), cleanup on `BufWipeout` of source, `WinClosed` of preview, and `VimLeavePre`.
5. Cell size: `Snacks.image.terminal.size()`, rounded `cell_width`/`cell_height` to integers. If snacks is not available, `vim.notify` an error and do nothing.
6. Server `type="error"` responses → `vim.notify(..., WARN)`; server exit while preview open → notify and close the preview.

**Check:** a headless smoke test, `tests/nvim/smoke.lua` run with `nvim --headless -u NONE --cmd 'set rtp^=.' -l tests/nvim/smoke.lua` after `cargo build`, with `cmd` pointed at `target/debug/dmbdip`: it stubs a global `Snacks` (`image.terminal.size()` returning fixed cell size 10×20, `columns`/`rows`; `image.terminal.request()` recording its opts), opens `docs/sample.md`, runs `:DmbdipPreview`, waits (`vim.wait`) for the first response, and asserts: preview buffer line count = `total_rows`; each line starts with `U+10EEEE`; recorded requests include one `a="t",t="t",f=24` per strip with `s=cols*10`, every request has no `q` override that disables silencing; after editing the source and waiting, at least one new transmit; after `:DmbdipPreview` again, `a="d"` requests for every id and the job has exited. Exits 0 on success, non-zero with a message otherwise. All Lua files parse. The real-kitty visual check (crisp text, scroll sync, no stray characters, `ls /dev/shm/dmbdip-*` empty after close) is done by the user afterwards. Commit `feat(nvim): live preview plugin using dmbdip --serve`.
